CORE IDEA

A frozen student p generates; an assistance system (teacher, monitor and decoding algorithm) turns it into an effective law Q. The price of assistance is KL(Q ‖ P) in bits. With unlimited control the cheapest always-successful Q is P(· | success), which costs exactly −log2 α, where α is the student's own success probability. Real teachers are restricted, so we measure the bits that a fixed, auditable assistance protocol needs to make the student succeed: every protocol ends with a guaranteed-success fallback, so each one is summarized by a single number, the expected certified bits per task.

  1. Protocol problem (Study A). For a given student and task, which teacher + monitor + injection algorithm reaches success with the fewest certified bits? Lower is a tighter upper bound on the student's information-injection cost.
  2. Evaluation problem (Study B). Across pretrained checkpoints, does the bit cost measured before post-training predict performance after equal-budget post-training, beyond validation loss, pass@k and teacher-answer likelihood?
CERTIFIED ACCOUNTING

Generation is split into blocks. Before each block the protocol picks one primitive from the history alone; each primitive has a pointwise bound Q(block | h) ≤ 2B p(block | h). A run costs the sum of B, and its expectation upper-bounds KL(Q ‖ P) by the chain rule.

primitivewhat happenscertified bits
FREEsample one block from p0
SELECT(K)sample K i.i.d. blocks from p; any rule keeps onelog2 K
FORCE(text)append teacher-written tokens−log2 p(text | h)
SELECT_OR_FORCEkeep a sample, or fall back to the textlog2(K + 1/p(text))
fallbackforce the reference solution as a fresh attempt; guarantees successits exact surprisal

Planning compute (reading the reference, student rollouts for value estimates, drafting hints) is free in bits but counted in compute. Reference points per task: reference = bits to force the whole reference solution (teacher-answer likelihood); free = the student alone, success rate α and the ideal −log2 α.

Final eval results

terminal-bench 10 · tau-bench 10 · AIME 2025 · IMO-AnswerBench

The settled testbed: 10 terminal-bench and 10 tau-bench retail tasks (multi-turn), the 30 AIME 2025 problems and the 400 IMO-AnswerBench v2 problems (graded by the final answer). Base models are measured by how many certified bits of teacher assistance they need (math: rejection sampling from the bare prompt, else the answer statement is injected; long horizon: per-turn injection of the benchmark's reference actions). Post-trained releases are measured by accuracy in their own chat format (Qwen3 with thinking). Question: does a base model's cost predict what its post-trained version solves? Design and predictions were written before any result (docs/FINAL_EVAL.md).

TERMINAL-BENCH · WHAT THE TEACHER INJECTS

The first measurement injected the benchmark's own solution scripts (a 60-line checker program costs ~1,300 bits to force), so its cost was mostly how surprising those scripts are. Rerun with short teacher trajectories for all ten tasks (Opus-written for three, Claude-written for seven, each verified to solve its task): forcing them, and per turn on them (the student proposes, the teacher injects only what is not accepted). DOES THE BASE MODEL KNOW THE ANSWER WITHOUT SOLVING? (INTEGER ANSWERS)

How often the base model finds the true answer more likely than each of its neighbours a±1, a±2 when it is simply stated after the problem, on all integer-answer problems and on those it never solved by sampling. Chance ≈ 20–25%. AIME 2025 is newer than these models' training data; IMO-AnswerBench problems come from public olympiad shortlists.
